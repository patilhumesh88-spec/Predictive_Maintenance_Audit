# Model Card: Leakage-Safe Predictive Maintenance Random Forest

## Model Details
- **Model Name:** Random Forest with Physics-Informed Feature Engineering
- **Model Type:** Scikit-learn `Pipeline` (ColumnTransformer with one-hot encoding for `Type` + passthrough numeric + `RandomForestClassifier`)
- **Hyperparameters:** `n_estimators=300`, `min_samples_leaf=2`, `class_weight="balanced_subsample"`, `random_state=42`
- **Package:** `maint_audit` v1.0.0
- **Threshold:** `0.515` (frozen based on out-of-fold F1 optimization on development data)

## Intended Use
- **Primary Use:** Demonstrating leakage-aware evaluation and auditing physical vs. statistical decision boundaries on industrial milling telemetry.
- **Out of Scope / Non-Goals:** Real-world factory deployment without physical validation. The benchmark is synthetic and lacks continuous time dynamics.

## Training Data & Leakage Discipline
- **Source:** UCI AI4I 2020 Predictive Maintenance Dataset (DOI: `10.24432/C5HS5C`, License: CC BY 4.0).
- **Size:** 10,000 observations (9,661 normal, 339 machine failures; 3.39% failure rate).
- **Features Used:**
  - Raw: `Type`, `Air temperature [K]`, `Process temperature [K]`, `Rotational speed [rpm]`, `Torque [Nm]`, `Tool wear [min]`
  - Derived Physics: `temp_diff` ($\Delta T$), `power_w` ($P = \tau \cdot \omega$), `wear_torque` ($w \cdot \tau$), `strain_ratio` ($w \cdot \tau / \text{limit}$)
- **Strict Leakage Exclusion:** Failure mode consequence flags (`TWF`, `HDF`, `PWF`, `OSF`, `RNF`) and record identifiers (`UDI`, `Product ID`) are permanently excluded from all model inputs.

## Evaluation & Metrics

### Out-of-Fold Validation (8,000 Development Rows, 5-Fold Stratified CV)
- **Physics Rules Alone:** F1 = `0.9267` [0.9019, 0.9472], AP = `0.8685` [0.8281, 0.9034], Precision = `1.0000`, Recall = `0.8633`
- **Random Forest ML:** F1 = `0.8936` [0.8633, 0.9181], AP = `0.9060` [0.8763, 0.9323], ROC-AUC = `0.9785`, Precision = `0.9545`, Recall = `0.8400`
- **Hybrid System (Rules OR ML >= 0.515):** F1 = `0.9072` [0.8801, 0.9307], AP = `0.9155` [0.8863, 0.9405], ROC-AUC = `0.9788`

### Final Holdout Evaluation (2,000 Untouched Rows, 39 Failures, Scored Once)
*Evaluated using the development-trained model:*
- **Rules Only:** TP = 28, FP = 0, FN = 11, Precision = 1.000, Recall = 0.7179, AP = 0.7234, ROC-AUC = 0.8590
- **Random Forest ML:** TP = 28, FP = 0, FN = 11, Precision = 1.000, Recall = 0.7179, AP = 0.7851, ROC-AUC = 0.9720
- **Hybrid:** TP = 28, FP = 0, FN = 11 (identical binary decisions; rules already cover the 28 detected failures)

## Generalization & Stress-Testing

### Leave-One-Failure-Mode-Out Test
When a failure mode is held out during training, ML fails to generalize to the unseen physical failure mode, whereas deterministic physics rules maintain 100% recall:
- **Held-out HDF:** Rules Recall = `100.0%` (115/115) vs. ML Recall = `7.83%` (9/115)
- **Held-out PWF:** Rules Recall = `100.0%` (85/85) vs. ML Recall = `14.12%` (12/85)
- **Held-out OSF:** Rules Recall = `100.0%` (77/77) vs. ML Recall = `10.39%` (8/77)

### Calibration & Operating Thresholds
- **Brier Score:** `0.0085`
- **Expected Calibration Error (ECE, 10 bins):** `0.0123` (1.23%)
- **Cost-Sensitive Thresholds ($C_{miss} : C_{fa}$):**
  - 1:1 $\rightarrow$ Optimal threshold = `0.515` (F1-optimal)
  - 10:1 $\rightarrow$ Optimal threshold = `0.300` (Recall = 87.3%, Cost reduction = 13.8%)
  - 100:1 $\rightarrow$ Optimal threshold = `0.015` (Recall = 97.0%, Cost reduction = 54.3%)

## Limitations
1. **Synthetic Telemetry:** Generated by simulation equations; lacks physical non-stationarity, sensor degradation, and real vibration dynamics.
2. **Holdout Imbalance:** The holdout split contains 0 HDF events (OSF=21, PWF=10, TWF=10), leaving HDF out-of-sample generalization unverified on the holdout.
3. **Stochastic Failures:** Tool Wear Failures (TWF) occur stochastically around 200–240 minutes. Tool wear is significantly elevated ($p < 10^{-16}$), but absence of pre-failure continuous warning signals makes statistical detection noisy.
